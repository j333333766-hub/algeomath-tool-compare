알지오매스와 해외 공학도구 비교

2026년 제3차 알지오매스 자문 회의(11. 17.) 검토 자료 · 2026. 11. 16. 작성

GeoGebra, Desmos, Polypad와 견주어 알지오매스 2.0과 신규 3D가 어디에 힘을 실어야 하는지, 그리고 시·도교육청 AIEP에 알지오매스를 탑재할 필요가 있는지를 정리했습니다.

GeoGebra·Desmos와 기능으로 경쟁하면 늦습니다. 알지오매스는 국가 플랫폼(AIEP) 안에 기본으로 들어가 있는 공공 탐구 도구, 한국 교육과정 순서대로 바로 쓰는 활동, 학생 탐구 과정을 남기는 데이터로 차별화하고, 신규 3D는 교육과정에 필요한 범위로 좁혀 빨리 내놓는 것이 좋겠습니다.

1비교 대상

  • GeoGebra: 기하·대수·3D·CAS·통계를 한 프로그램에 묶은 범용 도구. 고등학교에서 가장 자주 쓰는 도구입니다.
  • Desmos: 그래핑 계산기에서 기하·3D·문서(Notebook)로 넓혔고, 수업 활동 제작의 사실상 표준입니다.
  • Polypad: 가상 교구 중심이라 알지오매스키즈와 영역이 겹칩니다.
  • 참고: 통그라미·CODAP(통계 도구), GeoGebra Math Practice·MATHia·Khan Academy(단계별 대수 조작·학습 데이터 개인화)

4알지오매스의 위치

지켜야 할 강점

  1. 공공·국내 기반: 국내 서버와 개인정보 기준. 국가 정책사업·교육청 플랫폼과 직접 연결할 수 있는 유일한 도구
  2. 초등~고등 연속성: 키즈에서 2D·3D로. 해외에서는 Amplify만 이 방향으로 합치는 중
  3. 입체도형 탐구: 쌓기나무·전개도·회전체·단면은 중학교 핵심 내용. GeoGebra 3D에도 다면체 전개도는 있지만, 쌓기나무와 회전체를 직접 만들어 보는 활동형 기능은 해외 도구에 없음
  4. 블록코딩: 2D·3D 모두에서 학생이 코딩으로 작도. 정보 교과·AI 교육과 이어지는 고유 영역
  5. 국내 교사 공동체: 콘텐츠 약 82만 개, 모둠 9,600여 개, 교사 조사 1위

메워야 할 틈

  1. 3D 공간 작도·곡면 그래프: 신규 3D가 메울 영역. 하지만 따라잡기만으로는 차별점이 없음
  2. 공개 API·명령 체계: AIEP·교과서·교사 자작 콘텐츠 연계의 전제 조건
  3. 통계 도구: 통그라미·CODAP 수준의 데이터 탐색 도구가 없음
  4. 접근성: 공공 도구라면 화면 낭독·키보드 조작이 필요
  5. 탐구 과정 데이터: 학생이 어떻게 작도했는지 남지 않음
  6. 사용 지표 둔화: 신규 가입자 '23→'24 −19.4%, 모둠 수 '24→'25 −27.7%, 2026년 콘텐츠 수는 연 환산 약 13만 개로 '25년(29.7만 개)의 절반 이하

5임베드 API

공학도구가 수업과 데이터로 이어지려면 교사·기관이 자기 사이트에 도구를 넣고 학생 활동을 받아 볼 수 있어야 합니다. 이 점에서는 폴리패드가 가장 쉽고, 알지오매스는 담고 있는 정보는 가장 깊지만 꺼내 쓰는 문이 좁습니다.

현장 사례: 폴리패드 공식 API로 연수 사이트 만들기 (2026. 11. 14.)

  • 교사가 자기 사이트 주소로 폴리패드 API 키를 신청해 Firebase로 만든 연수 사이트에 넣었습니다.
  • 쓴 기능은 네 가지입니다. 캔버스 만들기(메뉴 줄이기), 바뀔 때 알림, 상태를 JSON으로 꺼내고 넣기, 놓인 타일만 그림으로 내보내기.
  • 이것으로 테셀레이션 미션별 제출(그림·타일 요약·조합), 8초마다 진행 과정 저장, 강사용 실시간 그림판을 한나절 만에 만들었습니다.
  • 데이터는 교사 사이트에만 쌓였고, 연수생은 폴리패드 계정이 필요 없었습니다.
  • 공식 문서를 보니 더 정교한 기능도 있었습니다. change 이벤트가 타일별로 [이전, 이후]를 주어 그림을 찍지 않아도 놓고 옮기고 지운 전체 과정을 남길 수 있고, 정답 판정(validate 이벤트, 두 상태 비교), 타일 메뉴·삭제·회전 끄기, 타일 잠금도 됩니다.
  • 이용 조건: 도메인을 적어 키 발급, 연 1만 회 미만 요청은 무료(상업 이용 포함), 그 이상·상표 제거·스크립트 자체 호스팅은 상업 라이선스. 응답 캐시·중계 금지, Amplify·Polypad 표시를 가리지 않기.
  • 따라서 교사 한 명의 연수·수업 규모는 무료로 충분하지만, 학교 전체·교육청·전국 플랫폼 규모는 상업 계약이 필요하고 오프라인으로는 쓸 수 없습니다. 주소는 최신판(latest)만 문서화돼 있고 2026년 v8.0.0에 호환이 깨지는 변경이 있었습니다.

알지오매스에 필요한 것

  1. 교사·연구자용 공개 API: 사이트 주소를 등록하면 키를 주고, 최소한 명령 실행, 상태 읽기·쓰기(형식 공개), 바뀔 때 알림, 그림 내보내기를 제공합니다. 이용 조건도 문서로 정합니다. 2.0 과제 1-③을 교육청 플랫폼 연계에서 여기까지 넓히는 것입니다.
  2. 알림 형식 = 학습 데이터 형식: 폴리패드의 알림은 "타일이 어디로 옮겨졌다" 수준입니다. 알지오매스가 "어떤 명령으로, 어떤 객체들을 써서, 무엇을 만들었다"를 알림으로 보내면 한 단계 더 깊은 학습 데이터가 되고, 임베드한 사이트(교사 사이트·AIEP·교육청 플랫폼)와 재단 학습저장소(xAPI)가 같은 자료를 받습니다. 명령시스템을 만들면 거의 덤으로 생기는 기능입니다.
  3. 데이터 두 갈래: 재단 저장소에 쌓는 길과, 폴리패드처럼 임베드한 기관이 직접 받는 길을 모두 열어 둡니다.
  4. 작도 판정 도우미: 의존 관계 정보를 살려 "점을 끌어도 수선의 발로 유지되는가" 같은 판정을 API로 주면, 과제 자동 채점·AI 평가와 바로 이어집니다.
  5. 알지오매스키즈 자유 캔버스: 교구를 골라 자유롭게 놓는 화면을 같은 API로 임베드할 수 있게 해 초등 영역을 지킵니다.

6모바일 사용성

알지오매스에서 본 문제

  1. 다각형 닫기: 꼭짓점 표시는 지름 약 8px인데 4px만 벗어나도 닫히지 않고, 알림 없이 점이 하나 더 생김
  2. 진행 상황이 안 보임: 점을 찍는 동안 변이 그려지지 않고, 끝내는 방법 안내·완성 단추도 없음
  3. 격자 맞춤 없음: 바닥 격자를 눌러도 교차점에 붙지 않아 반듯한 도형을 만들기 어려움
  4. 작은 단추: 위쪽 도구 단추 약 36px(애플 44pt·구글 48dp 권장보다 작음), 메뉴를 열면 작업 화면이 3분의 1~절반 가려짐
  5. 알지오2D 화면 넓이: 페이지 폭이 857px로 휴대폰 화면(412px)보다 넓어 옆으로 밀림

GeoGebra에서 본 것

  1. 첫 꼭짓점 둘레 약 27~40px 안을 누르면 닫힘. 2D와 3D가 같은 범위
  2. 점을 찍는 동안 변을 바로 그려 줌
  3. 꼭짓점 표시가 지름 약 14px로 더 큼
  4. 아래 대수창에 다각형(A, B, C)처럼 무엇이 만들어졌는지 글로 보여 줌

휴대폰이라 어쩔 수 없는 문제가 아니라 판정 범위 설정의 문제입니다.

개선 제안

  • 지금 알지오3D: 첫 꼭짓점 둘레 지름 48px 안을 누르면 닫히게 하고 가까이 가면 강조 표시, [완성] 단추나 마지막 점 두 번 누르기, 찍는 동안 미리보기 선, 방금 찍은 점만 취소, 도구 안내 한 줄, 격자 맞춤 켜고 끄기, 터치 화면에서는 점·단추 크게
  • 알지오2D: 휴대폰에서 옆으로 밀리지 않게 화면 너비에 맞추기
  • 신규 3D 로드맵: 1단계 '터치 입력'에 숫자 기준(누르는 대상 44~48px 이상, 기존 점 고르기·닫기 판정 지름 48px 이상), 검증 기기 목록(보급형 태블릿·터치 크롬북·아이패드·전자칠판·휴대폰), 단계마다 처음 쓰는 학생의 사용성 시험을 과업에 넣기

7개선 속도와 개발 방식

기능 하나가 현장에 오기까지 너무 오래 걸립니다. '25년 사이트 운영·기능 개선은 연 36건(한 달 3건 정도)이었고, '26년에도 행렬 편집기·입체도형 자르기·이차곡선 등 몇 가지를 한 해 과업으로 잡았습니다. 신규 3D는 2~4년을 예상합니다. 반면 AI 코딩 도구를 쓰면 새 기능을 만들어 수업에서 써 보는 데 드는 시간이 몇 시간에서 며칠로 줄었습니다.

현장 사례: 교사 한 명이 AI 코딩 도구로 더해 본 기능 (2026. 10. 3.~5.)

  • 알지오매스 2D·3D를 인터넷 없이 실행하는 수업용 시제품을 만들고, 그 위에 3D 기능을 더해 봤습니다.
  • 사흘 동안 더한 것: 자동 임시 저장·복구, STL·GLB·USDZ 내보내기(3D 프린팅·AR), 수식 입력창, 함수식 곡면, 방정식·매개변수 곡면, 슬라이더, 선분·직선·벡터·중점·평면·각뿔·각기둥·측정, 점 찍기·옮기기·되돌리기·터치.
  • 단계마다 자동 검사를 붙여 289개 검사를 통과했습니다. 신규 3D 로드맵 2~3단계에 나오는 곡면·슬라이더·입체 생성·측정을 시제품 수준에서 미리 써 볼 수 있었던 셈입니다.
  • 연수 사이트 도구도 요청한 날 만들어 배포하고 시험했습니다(예: 이 페이지 5절의 폴리패드 기록 방식 비교 화면).

시제품은 기존 엔진 위에 덧붙인 것이라 명령 처리·객체 의존 관계와 같은 핵심 구조까지 대신하지는 않습니다. 다만 "필요한 기능을 빨리 만들어 써 보고 판단하는 일"은 이제 현장에서도 할 수 있다는 것을 보여 줍니다.

제안: 두 갈래 개발 체계

① 실험실 · 며칠~2주

교사·자문단이 필요한 기능을 요청하면 AI 코딩 도구로 바로 시제품을 만들어, 별도 '알지오 실험실' 주소에서 수업에 써 보고 반응·오류를 모읍니다.

정식 서비스와 분리, "시범" 표시
② 정식 반영 · 격주~월 단위

실험실에서 검증된 기능만 골라 정식 코드로 다듬어 반영합니다. 수학적 정확성, 보안·개인정보, 접근성, 기존 파일 호환을 검사합니다.

공개 API·명령 체계가 있어야 실험실 기능을 붙였다 뗄 수 있음

과업 지시서에 넣을 것

  1. AI 코딩 도구 활용과 자동 검사(회귀 시험) 의무화. 기능마다 검사를 붙여, 고쳐도 다른 기능이 깨지지 않게 합니다.
  2. 배포 주기(예: 격주)와 오류 수정 목표 시간(예: 수업을 막는 오류는 48시간)을 적습니다.
  3. 성과 지표에 "요청부터 시범·반영까지 걸린 날수"를 넣습니다.
  4. 현장 요청과 오류는 누구나 보는 공개 게시판으로 받고 처리 상태를 공개합니다.
  5. 신규 3D는 "2~4년"을 단계별로 쪼개 첫 시범판을 몇 달 안에 내고, 수업 반응을 보며 넓힙니다.

업체가 AI 코딩 도구를 쓴다면

교사는 압축된 코드를 밖에서 들여다보며 우회해야 했는데도 사흘 만에 기능을 붙였습니다. 개발·운영 업체는 원본 소스·설계 의도·서버·배포 권한을 모두 가지고 있어, 같은 도구를 쓰면 효과가 더 큽니다.

빨라질 일

  1. 원인이 분명한 수정: 6절의 모바일 문제(닫힘 판정 범위, 미리보기 선, 단추 크기, 2D 화면 넘침)는 하루 안에 가능한 수준
  2. 현장 오류: 재현 → 원인 → 수정 → 다시 생기지 않게 막는 검사까지 한 흐름
  3. 기존 기능의 자동 검사 쌓기
  4. 명령·저장 형식·공개 API 문서 작성
  5. 현장 요청 기능의 시제품

사람 판단이 남는 일

  1. 명령시스템 같은 구조 개편: 기존 콘텐츠 약 82만 개와의 호환 검증이 핵심
  2. 수학적 정확성: 교점·부피·결과가 없는 경우의 처리는 교사·전문가 검토 필수
  3. 교육적 판단: 어떤 기능이 수업에 필요한지는 현장이 정함

걸림돌과 제안

  • 계약 구조: 기능 개선을 "투입 인력 × 기간"(연 14.2 MM, 221백만 원)으로 산정하면, AI로 빨리 끝내도 업체가 얻는 것이 없고 다음 해 예산 근거만 줄어듭니다. 반영한 기능 수, 요청부터 반영까지 걸린 날수, 오류 처리 시간 같은 결과로 평가해야 도구 효과가 현장까지 옵니다.
  • 보안 기준: 공공 서비스 소스를 외부 AI 서비스에 올리는 범위를 재단이 먼저 정해 줘야 업체가 쓸 수 있습니다.
  • 자동 검사가 전제: 검사 없이 AI로 빨리 고치기만 하면 오히려 오류가 늘 수 있습니다.
  • 시범 제안: 2027년 초 현장 요청 5~10건을 AI 활용 방식으로 처리해 지금 방식과 기간·품질을 비교합니다. 모바일 다각형 닫기 문제가 첫 과제로 알맞습니다. 같은 예산으로 더 많이 반영하는 쪽으로 쓰고, 신규 3D 일정도 이 전제로 다시 산정합니다.

AI로 만든 시제품도 교점·부피 계산, 결과가 없는 경우의 처리 같은 수학적 정확성을 검증해야 하고, 외부 코드·라이브러리의 라이선스 확인은 실험실에서도 똑같이 지켜야 합니다.

8발전 방향

GeoGebra·Desmos는 기능 폭에서 앞서 있고 무료입니다. 같은 기능을 늦게 만드는 것만으로는 선택받기 어려우므로, 해외 도구가 할 수 없는 일에 집중하고 따라잡기는 교육과정에 꼭 필요한 범위로 한정하는 편이 좋습니다.

A

국가 플랫폼 안으로 들어가기

AIEP·교과서·교육청 플랫폼에 기본 탑재되어, 학생이 따로 가입하지 않아도 수업 흐름 안에서 열리게 합니다. 근거: Desmos가 SAT 내장으로 확산된 것과 같은 원리입니다.

B

탐구 과정 데이터를 공공 자산으로

명령시스템 → xAPI 학습저장소 → 교사용 "작도 과정 다시 보기"와 AIEP 학급 대시보드로 이어지게 합니다. 근거: 해외 도구는 국내 개인정보 기준 때문에 교육청 플랫폼과 학생 데이터를 깊게 연결하기 어렵습니다.

C

교육과정 순서대로 바로 쓰는 활동 묶음

단원별로 복사해서 바로 쓰는 모둠 과제와 5분 탐구 묶음을 만듭니다. 근거: Desmos Activity Builder와 GeoGebra 자료실의 강점이 '바로 쓰는 활동'이고, 국내 교과서 순서 자료는 알지오매스가 유리합니다.

D

초등 교구에서 중등 도구로 연결

키즈의 조작 교구가 2D·3D로 자연스럽게 이어지게 합니다. 근거: Amplify가 Polypad와 Desmos를 합쳐 같은 그림을 그리는 중입니다.

E

신규 3D는 범위를 좁혀 빨리

고등 기하와 중학교 입체도형에 필요한 기능부터 만들고, 기존 3D의 전개도·회전체 단면과 합칠 계획을 함께 세웁니다. 근거: GeoGebra 3D 전체를 재현할 필요는 없습니다. 현장 교사가 기존 엔진 위에서 곡면·슬라이더·측정 시제품을 몇 주 만에 만든 사례도 있어, 범위를 좁히면 "2~4년"을 줄일 수 있습니다.

F

공개 API와 명령 문서

2D·3D 공통 명령 규격을 공개 문서로 내면 교사·업체·교육청이 알지오매스를 끼워 넣어 콘텐츠를 만들 수 있습니다. 근거: GeoGebra가 수많은 교과서와 사이트에 들어간 이유가 공식 Apps API입니다.

G

통계 도구와 접근성

통계는 CODAP 방식을 참고해 별도로 연구하고, 접근성은 공공 도구의 의무로 단계적으로 도입합니다. 근거: 통그라미 12.4% 수요, Desmos 접근성 사례.

H

AI는 조작할 수 있는 대상으로 바꾸는 데

손글씨·음성을 명령으로 바꿔 객체를 만듭니다. 명령시스템 위에서 만들어야 기록과 되돌리기가 됩니다. 근거: 해외 도구의 AI는 아직 풀이·튜터 쪽이고, 이 방향은 2.0 문서가 내세운 차별점과 일치합니다.

9AIEP 탑재

AIEP는 무엇인가

  • 인공지능 맞춤형 교수학습 플랫폼(AIEP): 서울·인천 등 11개 시·도교육청이 공동 구축했습니다. 구글·웨일 등의 학습관리시스템을 바탕으로 수업 관리를 하나로 모으고, 통합 로그인(SSO)으로 여러 에듀테크를 한 계정으로 쓰게 하며, AI 학급 대시보드로 학습 현황을 보여 줍니다.
  • 인천: AIEP 통합서비스를 개통해 빅테크·에듀테크와 교육청 자체 플랫폼을 한 화면에 모았습니다. 수학은 매쓰홀릭T·홀링 등 국산 학습 서비스가 연계돼 있습니다.
  • 전북: AI 디지털 선도학교 100개교 시범 뒤 하반기 전면 도입.

지금 AIEP 수학 메뉴는 문항·학습 서비스 중심이고 탐구형 공학도구 자리는 비어 있습니다. 공공 무료 도구인 알지오매스가 들어갈 명분이 분명합니다.

필요한 이유

  1. 진입 장벽 제거: AIEP 계정 하나로 바로 열면 가입·로그인 부담이 사라짐
  2. AIDT 이후 공백: '25년 AIDT 지위 변경으로 연계가 줄었음('25년 도구 로딩 약 77만 건). AIEP가 그 통로를 이어받음
  3. 데이터 환류: 모둠 과제 결과와 탐구 기록을 학급 대시보드로 보내면 2.0 전략 3(데이터 기반 맞춤 지원)의 실제 사용처가 생김
